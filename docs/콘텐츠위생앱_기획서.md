## 1. 한 줄 정의

공공기관 홈페이지를 **읽기 전용으로 전수 스캔**해 중복·오표기·낡은 정보·사실 충돌을 찾아내고, **사람의 승인**을 거쳐
① 부서별 수정 요청서와 ② 챗봇·검색이 바로 쓸 수 있는 **RAG 인덱스 매니페스트**를 만들어 주는 진단·감시 도구.

## 2. 배경과 문제

### 2.1 왜 필요한가

RAG 챗봇은 홈페이지 콘텐츠를 그대로 읽는다. 같은 문서가 5벌 있으면 검색 점수가 오염되고, 낡은 페이지가 남아 있으면 AI는 그것을 자신 있게 읽어 준다. 강의안의 표현대로 "AI는 홈페이지의 거울"이고, 콘텐츠 위생 없는 AI 개편은 오답 생성기를 사는 일이다.
행안부 「공공부문 AI 도입·활용 가이드」(2026-06-10)의 RAG 우선 원칙도 '기관 내부의 정확한 최신 문서'를 전제로 한다(강의안 23번 인용, 원문 재확인 필요). 그 전제를 만들어 주는 도구가 없다는 것이 이 제품의 출발점이다.

### 2.2 마포구에서 관찰된 문제 → 제품 기능 매핑

| # | 관찰된 문제 (강의안 7·8번) | AI에 미치는 영향 | 담당 탐지기 |
|---|---|---|---|
| 1 | silver·mangwon1·culture·edu 도메인에서 대표사이트 페이지가 그대로 열리고 색인됨, canonical 부재 | 같은 문서 여러 벌 → 검색 점수 오염 | D1 중복 |
| 2 | 모든 하위 도메인 title이 동일, 주택/건축 민원·부서안내가 "민원실 종합안내"로 색인, china·japan title 누락 | 챗봇 출처 표기에 엉뚱한 제목 노출 | D2 title |
| 3 | '코로나19 확진자 이동경로', '민선8기 비전' 페이지 잔존 | 낡은 문서를 근거로 자신 있게 오답 | D3 낡음 |
| 4 | 고시공고 게시판 이원화(2023-07-19 이전 게시판 + nPortal) | 어느 쪽을 읽느냐에 따라 답이 갈림 | D4 게시판 이원화 |
| 5 | 게시판 URL에 상태 파라미터 9개 노출, `&amp=&` 이스케이프 버그 | 같은 페이지가 수십 개 URL로 보임 | ② 정규화 + D5 |
| 6 | 민원 안내가 PDF·HWP 첨부에 의존 | 표 안의 수수료·준비물을 AI가 못 읽음 | D6 첨부 의존 |
| 7 | (일반) 같은 수수료·전화·운영시간이 페이지마다 다를 가능성 | 틀린 답의 직접 원인 | D7 사실 충돌 |
| 8 | (일반) 게시글·첨부 속 개인정보 노출 가능성 | 개인정보 유출 + AI가 이를 재노출 | D8 개인정보 |

### 2.3 기존 방식의 한계

- **수작업 전수 점검 불가** — 디지털정책팀 4명이 28개 사이트를 겸임한다(강의안 4번).
- **범용 SEO 크롤러** — 중복·죽은 링크는 잡지만 '낡음의 의미 판단', '사실 충돌', 'HWP 첨부', 'RAG에 넣을지 말지'라는 관점이 없다.
- **챗봇 구축 사업** — 콘텐츠 정비는 대개 과업 밖이거나 검수 기준이 없다. 강의안이 "콘텐츠 정비를 별도 과업·별도 검수로 분리"하라고 권고한 이유다.

## 3. 목표와 비목표

### 목표
- **G1** 28개 사이트의 위생 상태를 2주 안에 숫자로 제시한다(중복률, title 오류 수, 낡은 페이지 수, 사실 충돌 건수, 죽은 링크 수).
- **G2** 원본 수정이 끝나기 전에도 챗봇이 깨끗한 문서만 읽도록 RAG 인덱스 매니페스트를 제공한다.
- **G3** 승인 1건에 10초(중앙값)가 걸리도록 설계해, 4명이 감당할 수 있는 운영 부하로 만든다.
- **G4** 강의안 KPI ⑦ '콘텐츠 신선도'(90일 미갱신 페이지·중복률·title 오류 수)를 매주 자동 산출한다.
- **G5** 산출물(매니페스트·규칙·골드셋·이력)을 전부 기관 소유로 남겨 벤더 종속을 막는다.

### 비목표
- **N1** CMS를 직접 수정하지 않는다. 자동 삭제도 없다.
- **N2** 챗봇·검색엔진 자체를 만들지 않는다. 그들의 입력을 깨끗하게 만든다.
- **N3** 웹 접근성 인증 심사를 대체하지 않는다(가벼운 점검은 확장 단계에서 검토).
- **N4** 로그인 영역, 새올전자민원의 신청·처리 화면은 수집하지 않는다(링크 생존 확인만).
- **N5** 법적 판단을 하지 않는다. 고시공고의 효력·보존은 담당 부서가 결정한다.

## 4. 사용자와 시나리오

| 사용자 | 하는 일 | 앱에서 받는 것 |
|---|---|---|
| 디지털정책팀 담당자(승인자) | 이슈 검토·승인, 규칙 관리, 월간 보고 | 이슈 큐, 대시보드, KPI 리포트 |
| 부서 콘텐츠 담당자 | 자기 부서 페이지 수정 | 쉬운 말로 쓴 엑셀 수정 요청서(로그인 불필요) |
| 챗봇·검색 구축 벤더 | 인덱싱 | 매니페스트 JSON, canonical 맵 |
| 텐에이아이 진단 컨설턴트 | 2주 진단 수행, 골드셋 라벨링 | CLI, 진단 리포트 초안 |

**시나리오 S1 — 2주 진단(발주 전)**
첫날 크롤 시작 → 3일차 중복·title·URL 1차 리포트 → 2주차 낡음·게시판 이원화·사실 충돌·개인정보 → 매니페스트 v0과 과업지시서용 수치 제출.

**시나리오 S2 — 주간 감시(운영)**
매주 증분 크롤 → 새로 생긴 이슈만 알림 → 담당자가 월요일 30분 안에 승인 → 부서별 요청서 자동 발송 → 월말 KPI 공개.

**시나리오 S3 — 벤더 인계**
낙찰 벤더가 매니페스트 엔드포인트를 읽어 포함/제외/대표 URL을 그대로 반영. 벤더가 바뀌어도 매니페스트는 유지.

**시나리오 S4 — 계약 전 외부 스캔(영업)**
전부 공개 페이지이므로 저속·소량 표본 스캔만으로 "중복률 N%, 낡은 페이지 N건" 1쪽 리포트를 만들어 첫 미팅에 가져간다. (robots.txt 준수, 표본 상한 준수)

## 5. 핵심 설계 원칙

1. **읽기만 한다** — 크롤링으로만 읽고, 모든 처분(갱신·보관·인덱스 제외)은 사람이 승인한다. 고시공고의 '폐기'는 삭제가 아니라 '보관 표시 + 인덱스 제외'다.
2. **산출물은 두 갈래** — 원본을 고치는 길(수정 요청서)은 느리고, 인덱스를 보호하는 길(매니페스트)은 빠르다. 둘을 동시에 낸다.
3. **싼 판단 먼저** — 규칙 → 유사도 → LLM → 사람. LLM은 의미 판단이 필요한 일부 문서에만 쓴다.
4. **측정되는 도구** — 탐지기마다 골드셋으로 정밀도를 재고, 90% 미만이면 '자동 제안'이 아닌 '관찰' 등급으로만 보여 준다.

## 6. 기능 범위

### 6.1 파이프라인

`① 수집 → ② 정규화 → ③ 탐지 → ④ 채점 → ⑤ 조치(승인·내보내기) → ⑥ 감시`

### 6.2 탐지기 8종

| 탐지기 | 잡는 것 | 방법 요약 | LLM | 단계 |
|---|---|---|---|---|
| D1 중복 | 도메인 간·URL 변형 중복 | SHA-256 + MinHash, 대표 URL 선정 규칙 | 불필요 | MVP 1주차 |
| D2 title | 누락·전 사이트 동일·h1 불일치·의미 불일치 | 규칙 → 임베딩 유사도 → LLM 판정·제안 | 일부 | 규칙 1주차 / LLM 2주차 |
| D3 낡음 | 기한 만료·대체됨·조직개편 전 정보 | 날짜·기간·키워드 사전·죽은 링크·조직도 대조 → LLM 분류 | 일부 | 2주차 |
| D4 게시판 이원화 | 구·신 게시판 중복·불일치 | 제목+게시일+고시번호 매칭 | 불필요 | 2주차 |
| D5 URL·링크 | 파라미터 오염, 이스케이프 버그, 죽은 링크, 고아 페이지 | 규칙 | 불필요 | 1주차 |
| D6 첨부 의존 | 핵심 정보가 HWP·PDF에만 있음 | 첨부 추출 → 구조화 초안 | 필요 | 파일럿 |
| D7 사실 충돌 | 같은 대상의 수수료·전화·시간 불일치 | 사실 추출 → 정규화 → 불일치 탐지 | 필요 | 2주차 |
| D8 개인정보 | 주민번호·휴대전화 등 노출 | 정규식 + 화이트리스트 | 불필요 | 2주차 |

### 6.3 화면 5종 (파일럿 단계)

1. **대시보드** — 사이트별 위생 점수, KPI ⑦ 추이, 이번 주 새 이슈
2. **이슈 큐** — 필터(유형·부서·심각도), 증거 나란히 보기, 단축키 승인, 묶음 승인
3. **중복 클러스터** — 같은 문서의 URL 묶음, 대표 URL 선택
4. **규칙 편집** — 시한 키워드 사전, 잡음 파라미터, 시민 작성 게시판 목록
5. **내보내기** — 수정 요청서(엑셀), 매니페스트, canonical·리다이렉트 맵, KPI

## 7. 성공 지표

**7.1 제품 품질**
- 회귀 사례(강의안 관찰 9건 중 현재도 재현되는 것) 자동 재발견율 100%
- '자동 제안' 등급 탐지기의 정밀도 ≥ 90% (탐지기별 300건 골드셋)
- 승인 1건 처리 시간 중앙값 ≤ 10초
- LLM이 낸 모든 판정에 본문 인용 근거가 붙어 있고, 인용이 본문에 실재함(코드로 검증) 100%

**7.2 고객 성과 (매주 자동 산출)**
- 중복률 = 비대표 URL 수 ÷ 전체 수집 URL 수
- title 오류 수, 90일 미갱신 페이지 수, 기한 만료 페이지 수, 사실 충돌 건수, 죽은 링크 수
- 매니페스트 '포함' 문서 비율과 그 추이
- 이 수치들은 챗봇 '출처 있는 정답률'(강의안 KPI ①)의 선행 지표로 함께 보고한다.

**7.3 사업**
- 진단 → 파일럿 → 월간 감시로 이어지는 전환 여부, 2번째 기관 적용 시 재사용률(규칙·코드)

## 8. 제도·보안 정합성

| 요구 | 설계 반영 |
|---|---|
| RAG 우선·정확한 최신 문서(행안부 가이드) | 매니페스트가 '정확한 최신 문서' 목록 그 자체. 갱신 주기 = 주 1회 |
| 개인정보 보호 | D8로 노출 탐지, 저장은 마스킹본만, LLM 전송 전 마스킹, 시민 작성 게시판은 LLM에 보내지 않음 |
| N2SF | 공개 웹페이지만 다루므로 O 등급 상정 — 정보통신팀과 합의 필요 `(확인 필요)` |
| CSAP | 개발·진단은 자체 환경, 기관 납품·운영은 CSAP 인증 리전 |
| 모델 정책 | 국산 CSAP API 우선, 중국계 모델·임베딩 제외, 어댑터 구조로 TenOS-Ko-28B 등과 교체 비교 |
| 기록물 성격의 게시물 | 고시공고는 삭제 제안 금지. '보관 + 인덱스 제외'만 제안 |
| 크롤링 예절 | robots.txt 준수, 원 서버 단위 속도 제한, 야간 실행, 오류율 급증 시 자동 중단, 식별 가능한 User-Agent |
| 보안관제 | 계약 후 수집 IP·일정을 정보통신팀에 사전 통보(공격 오탐 방지) |
| AI 생성물 표시 | AI 초안(title 제안·구조화·요약)에는 '초안' 표시와 원문 근거를 붙이고 사람 검수를 거침 |
| 소유권 | 매니페스트·규칙·골드셋·이력은 기관 소유로 계약서에 명시 |

> 제도 명칭·시행일은 강의안 38번 기준이다. 제안서·계약서에 인용하기 전에 원문을 다시 확인한다.

## 9. 비용 추정

### 9.1 모델비 — 전수 스캔 1회 `(추정)`

가정: 정규화 후 고유 문서 3만 건, 문서당 1,500~2,000 토큰, 강의안 가격표의 경량 모델 단가(입력 $0.25·출력 $1.50/100만 토큰), 임베딩 $0.02/100만 토큰, 환율 1,345원.

| 항목 | 물량 | 비용 |
|---|---|---|
| 임베딩(전체) | 4,500만 토큰 | 약 1천 원 |
| title·낡음 판정(의심 20%) | 입력 1,200만 + 출력 120만 토큰 | 약 7천 원 |
| 사실 추출(전체) | 입력 6,000만 + 출력 900만 토큰 | 약 4만 원 |
| **합계** | | **5만 원 안팎** |

페이지 수가 10배여도 50만 원 수준이다. 실제 페이지 수는 첫 크롤 후 확정한다 `(확인 필요)`.

### 9.2 인프라
- GPU 없음. 4 vCPU·16GB급 서버 1대 + 저장공간 100GB `(추정)`. 진단 단계는 노트북으로도 가능.
- 요금은 CSAP 사업자 요금계산기로 확인 `(확인 필요)`.

### 9.3 인력 `(추정)`
- MVP 2주: 개발 1명(AI 코딩 도구 활용) + 컨설턴트 0.5명(골드셋 라벨링·리포트)
- 파일럿 8주: 개발 1명 + 프론트 0.5명 + 컨설턴트 0.5명
- 비용의 본체는 모델이 아니라 **사람의 검토 시간**이다. 그래서 G3(10초 승인)이 핵심 요구사항이다.

### 9.4 수집 소요 시간 `(추정)`
- 초당 1요청 × 야간 8시간 = 하룻밤 약 2.9만 건. 고유 URL 3만~10만 건이면 1~4일 밤.
- 하위 도메인이 같은 원 서버를 쓰면 병렬화 이득이 없다. 계약 후 정보통신팀과 속도 상향을 협의한다.
- 따라서 **수집기는 1주차 1~2일 안에 완성해 먼저 돌리고**, 수집이 도는 동안 탐지기를 만든다.

## 11. 사업화

**포지셔닝** — "챗봇을 다시 만들기 전에, 챗봇이 읽을 것을 먼저 검진한다." 챗봇 벤더와 경쟁하지 않고 그들의 입력을 깨끗하게 해 주는 위치이므로 어떤 벤더와도 병행된다.

**공무원에게 건네는 한 문장** — "AI 도입 전 홈페이지 건강검진. 2주, 서버 구매 0원, 결과물은 전부 기관 소유."

**상품 구성**

| 상품 | 내용 | 조달 경로 |
|---|---|---|
| ① 건강검진(1회) | 전수 스캔 + 진단 리포트 + 매니페스트 v0 + 과업지시서용 수치 | 소액 수의계약 범위 내 설계(강의안 기준 한도 2천만 원, 확인 필요) |
| ② 정비 파일럿(8주) | 승인 워크플로·감시·구조화 초안 | 본사업의 '콘텐츠 정비' 분리 과업 또는 별도 용역 |
| ③ 월간 감시(구독) | 주간 증분 스캔 + 월간 KPI 리포트 + 매니페스트 갱신 | 장기적으로 디지털서비스 전문계약 등록 검토 |

- 구독 가격은 정하지 않았다. 파일럿에서 운영 공수를 실측한 뒤 산정한다.
- 교육 결합: 부서 담당자 대상 '웹 콘텐츠를 AI가 읽기 좋게 쓰는 법' 교육을 ②에 묶으면 정비가 일회성으로 끝나지 않는다.

**인접 도구와의 차별점**

| 인접 도구 | 하는 일 | 이 제품이 더하는 것 |
|---|---|---|
| 범용 SEO 크롤러 | 중복·죽은 링크·메타 | 낡음의 의미 판단, 사실 충돌, HWP 첨부, RAG 매니페스트, 승인 워크플로 |
| 웹 접근성 점검 도구 | 대체텍스트·명도 등 | 콘텐츠의 '내용' 품질 |
| 챗봇 구축사의 데이터 정제 | 자사 인덱스 한정 정제 | 벤더 중립 산출물, 기관 소유, 원본 수정까지 연결 |

**확장 시장** — 기초·광역 지자체, 지방공기업, 교육청·도서관 등 다수 사이트를 소수 인원이 운영하는 기관. 마포에서 검증한 규칙(고시공고·조직개편·HWP)은 다른 지자체에 거의 그대로 적용된다.
